# 2.1.163 ◆◆◆◆

[Back to the changelog](../README.md#changelog)

- 🔴 Added recovery for sessions that sign in with a token from the environment and hit a 401 they can't refresh: Claude Code waits for a rotated `CLAUDE_CODE_OAUTH_TOKEN` (up to `CLAUDE_CODE_OAUTH_401_WAIT_MS`; 60 seconds by default in cloud sessions, otherwise no wait), and a cloud session still failing after `CLAUDE_CODE_AUTH_FAIL_EXIT_MS` (10 minutes by default) exits so its runner restarts it with fresh credentials.
- 🔴 Changed a refresh token the server rejects as dead to be cleared from the saved credentials, and treated an empty saved refresh token as dead, so later sessions stop retrying it.
- 🔴 Made fetching, messaging and polling cloud sessions stop early on providers other than the Anthropic API, with "Remote sessions are only available on the first-party Anthropic API provider." (creating one already did), and skipped archiving them there.
- 🔴 Added the cloud environment manager's latest log line as the status text in `claude --remote` and attached session views.
- 🔴 Changed remote session views to dismiss a permission prompt that was answered elsewhere or left open when the turn ended, and to ignore the echo of their own model switch; denying a prompt without feedback, or cancelling it, now also interrupts the turn, except in read-only viewers.
- 🔴 Changed slash commands in `claude --remote` and attached sessions to run locally, go to the remote session, or be refused, depending on the command and whether the session takes control requests; read-only viewers get "/name isn't available while viewing read-only", and `!` shell commands are refused with "'!' commands aren't available in remote sessions yet".
- 🔴 Changed `/session` in a remote session with no browser link to explain why (the session is connected directly, or the link isn't available from this view) instead of saying it isn't in remote mode.
- 🔴 Stopped Remote Control from sending your git remote when the repository's root is your home folder (for example a dotfiles repository).
- 🔴 Made Remote Control run as a background daemon service record the environment it registered for its folder in a pointer file (refreshed hourly) and ask to reuse it after a restart, so earlier sessions can reconnect; while the process that wrote the pointer is still running, it registers a new environment instead.
- 🔴 Changed permission answers from Remote Control that switch the permission mode to go through the session's mode checks; a mode the session can't use falls back to `default`.
- 🔴 Added team memory indexes to the auto-memory prompt: for each `CLAUDE_MEMORY_STORES` entry with a `promptIndex`, the index fetched from memory-service (5-second limit) is included as reference data, or Claude is told how to start one.
- 🔴 Added a `scope` field to `CLAUDE_MEMORY_STORES` entries (`team` by default); one `user` entry syncs your personal memory folder with that store.
- 🔴 Made a self-paced `/loop` end when Claude declines to reschedule twice in a row, so the fallback wakeup fires only once (self-paced loops sit behind the remote switch `tengu_kairos_loop_dynamic`, off by default).
- 🔴 Changed the terminal UI to draw Unicode bidirectional control characters (U+061C, U+202A to U+202E, U+2066 to U+2069) as `�` instead of hiding them, and to replace them before laying out text in Windows Terminal and VS Code's terminal.
- 🔴 Added a remote switch, `tengu_native_cursor` (off by default), that turns on the terminal's native cursor where it works, as `CLAUDE_CODE_NATIVE_CURSOR` does.
- 🔴 Added a regrouped `/config` (Appearance, Model & output, Display, Input & controls, Connections, Advanced, Experimental, Internal) with reworded setting labels, plus hidden `/vim` and `/output-style` commands that point to their settings in `/config`, all behind the remote switch `tengu_maple_sundial` (off by default).
- 🔴 Added kind lanes and source tags to the `/` menu (config, agent, skill; `[project]`, `[org]`) with short descriptions for bundled skills, behind `CLAUDE_CODE_ENABLE_MENU_KIND_LANES` or the remote switch `tengu_mint_lanes` (both off by default).
- 🔴 Stopped OSC escape sequences, such as terminal hyperlinks, from showing up as stray characters in screenshots copied to the clipboard.
- 🔴 Changed a Bash allow rule that names the whole command so it no longer skips broader deny and ask rules or the checks on redirects and paths; before, such a rule allowed the command at once.
- 🔴 Stopped wildcard Bash allow rules from also allowing the same command run through `xargs` unless the pattern ends in `*`; deny and ask rules still match the `xargs` form.
- 🔴 Made Bash permission checks on writes into a git folder's `HEAD`, `objects`, `refs` or `hooks` follow symlinks, and treat a path that climbs out of a symlinked folder with `..` as such a write.
- 🔴 Tightened Bash read-only checks: a flag value that comes from `$(…)` or from a variable whose value can't be determined no longer counts as safe, and backticks are now understood when scanning a command for unquoted globs, brace tricks and variable expansion.
- 🔴 Made EnterWorktree register the new worktree with the Bash sandbox, and opened the main repository's git folder of each session worktree to sandboxed writes, except its `hooks` and `config`.
- 🔴 Changed PowerShell permission checks to skip `#` comment lines, read `~` as your home folder, and keep drive letters (a bare `C:` is read as the current folder).
- 🔴 Stopped AskUserQuestion's permission step from passing on `answers` that Claude put in its own input; only the questions and their metadata reach the prompt.
- 🔴 Narrowed WebFetch's pre-approved documentation sites: `wordpress.org`, `huggingface.co` and `www.kaggle.com` now cover only their documentation paths, `nuget.org` was removed, and a URL path with an encoded `/`, `\` or `.` no longer matches a path-limited entry.
- 🔴 Stopped showing the managed-settings approval dialog in sessions signed in through a Cloud gateway.
- 🔴 Stopped fetching remote managed settings in `remote_cowork` sessions, as already for `local-agent`.
- 🔴 Let an agent's `tools` list name an MCP server (`mcp__server` or `mcp__server__*`) to get all of that server's tools; before, such an entry matched nothing.
- 🔴 Allowed Haiku 4.5 as the main model for the advisor (`/advisor`, `--advisor`).
- 🔴 Changed Sonnet 4.6 and Opus 4.6 below 1M context to a 200K auto-compact window that counts as one you set, so they compact before the context fills instead of waiting for it to overflow.
- 🔴 Added an alternative "Communicating with the user" system-prompt section (write for a teammate catching up, lead with the outcome, prefer readable to terse, comment code sparingly) and the autonomy section for models named by the account's `velvet_falcon_model` setting or the remote switch `tengu_velvet_falcon_model` (empty by default); `CLAUDE_CODE_VELVET_FALCON` forces it on or off for every model.
- 🔴 Locked down dynamic workflow scripts: they run without `eval`, code built from strings or WebAssembly, built-in objects can't be modified, and risky globals are removed; `with`, `await using` and identifiers starting `__wRg$` are rejected; arrays in copied agent options and results and in child-workflow arguments and results, including nested arrays, now have at most 4,096 elements, and one `parallel()` or `pipeline()` call also takes at most 4,096 items, as the Workflow tool's description now states. Workflow console output uses a bracketed type such as `[object]` only when a value can't be turned into JSON, while child workflows' `log()` uses bracketed types for values that aren't text.
- 🔴 Allowed a workflow to return an object containing functions: if the normal copy fails, the main result is copied through JSON with function-valued properties left out.
- 🔴 Changed Claude in Chrome tool descriptions: `javascript_exec` evaluates with REPL rules (top-level `await` works), and `file_upload` accepts only files shared with the session, under 10 MB per call.
- 🔴 Fixed Claude in Chrome tool calls failing at once while a bridge reconnect was scheduled; they now wait for it, up to 10 seconds.
- 🔴 Added warnings when two enabled plugins' LSP servers claim the same file extension, or one plugin declares two, naming the server that's used and what to disable.
- 🔴 Made `claude plugin validate` on a marketplace also check the `plugin.json` of each plugin it lists with a `./` path, prefixing findings with `plugins[N] plugin.json →`.
- 🔴 Accepted `"."` as a plugin's `source` in `marketplace.json`, read as `"./"`.
- 🔴 Stopped `/plugin` command suggestions from showing `vunknown` for a plugin whose version is unknown.
- 🔴 Added a warning to `/reload-plugins` when the reload adds or removes MCP tools mid-conversation with tool search off, since the next message would re-read the whole conversation without the cache; `/reload-plugins --force` applies it anyway.
- 🔴 Added an "MCP servers" section to `/doctor` listing servers that failed or need authentication, also included in its fix prompt, and stopped Enter from dismissing `/doctor` while its first installation check is still running (Escape still closes it).
- 🔴 Made `/code-review ultra` and `claude ultrareview` refuse a branch diff over 500 files or 50,000 changed lines (limits that can be set remotely), suggesting a PR number or a closer base branch.
- 🔴 Added a bundled `cowork-plugin` skill for creating or customizing Cowork plugins, available to Claude only under the `remote_cowork` entrypoint.
- 🔴 Updated the bundled `claude-api` skill with a token-counting guide (`messages.count_tokens`, never `tiktoken`) and a rewritten description that tells Claude to load it for any Claude, Anthropic or provider-unstated LLM task unless another provider is in use.
- 🔴 Reworked the bundled `/design-sync` skill for Storybook repositories: it now ships the built Storybook as `_sb/` and draws each component's preview from it, with new probe, build, emit, validate and local-server scripts; the DesignSync access prompt no longer says the added scopes persist. Behind the remote switch `tengu_slate_quill` (off by default).
- 🔴 Added `user:design:read` and `user:design:write` to the token-refresh request made when you approve DesignSync access; before, it asked only for the usual Claude Code scopes.
- 🔴 Expanded the bundled `/design-sync` skill's package-only troubleshooting with fixes for font imports, generated props, provider names and adapter overrides, and clarified how rebuild commands and repository notes are used during re-sync.
- 🔴 Removed callback, shared-memory and debug globals from the JavaScript REPL tool, made more built-in objects read-only, and stopped scripts from adding `globalThis.then`; the REPL still allows code built from strings, and it's turned on with `CLAUDE_CODE_REPL` or the remote switch `tengu_slate_harbor`.
- 🔴 Fixed multi-store memory sync forgetting a file edit made while an earlier upload was running; the newer edit now stays queued for another upload.
- 🔴 Stopped Bash checks from statically analyzing `for` loops that overwrite a variable assigned a literal value earlier in the command, and made them track assignments behind command wrappers and `!` when following later variable changes.
- 🔴 Changed skill, command and agent frontmatter parsing to retry with leading tabs turned into spaces when the YAML doesn't parse.
- 🔴 Rejected worktree names with a `.git` path segment (any letter case, trailing dots ignored).
- 🔴 Added a `reload_skills` SDK control request that, when `CLAUDE_CODE_SYNC_SKILLS` is set, fetches the current cloud skills again after any sync already running (up to `CLAUDE_CODE_SYNC_SKILLS_INSTALL_TIMEOUT_MS`, 30 seconds by default), then reloads skills from disk and returns the refreshed list.
- 🔴 Made the `update_environment_variables` SDK request send a success reply when it carries a `request_id`.
- 🔴 Added hermetic mode for cloud sessions (`CLAUDE_CODE_REMOTE_HERMETIC_MODE` with `CLAUDE_CODE_REMOTE`): project and local MCP servers are skipped, and only SDK servers are taken from `--mcp-config` and SDK server updates.
- 🔴 Made SDK MCP server updates ignore the built-in servers the CLI owns, reporting "Builtin server is CLI-owned; ignored".
- 🔴 Added an `api_refusal` OpenTelemetry event (model and request ID) when a response ends as a refusal.
- 🔴 Stopped `claude update` and `claude upgrade` from capturing early keyboard input.
- 🔴 Made the SDK's `reload_plugins` request fetch the current cloud plugins again before reloading them when `CLAUDE_CODE_SYNC_PLUGINS` is set, after any sync already running; the wait lasts up to `CLAUDE_CODE_SYNC_PLUGINS_INSTALL_TIMEOUT_MS` (30 seconds by default) before it goes on with the files available.
- 🟡 (2.1.302) Made `CLAUDE_CODE_FORK_SUBAGENT` set to a false value (such as `0`) turn fork subagents off even where the remote rollout turns them on.
- 🟡 (2.1.223) Stopped dynamic workflow scripts from loading code through `import()`.
- 🟡 (1.0.43) Handled the write error when an async hook exits without reading its input; it's now logged instead of surfacing as an uncaught error.
- 🟢 Added the `requiredMinimumVersion` and `requiredMaximumVersion` managed settings: Claude Code refuses to start outside that range (except `update`, `install` and `doctor`) with instructions, and auto-update and `claude update` skip versions above the maximum.
- 🟢 Added `/plugin list` with `--enabled` and `--disabled` filters, listing each installed plugin's version, scope and state.
- 🟢 Added `c` to `/btw` to copy the answer's raw markdown to the clipboard.
- 🟢 Added `hookSpecificOutput.additionalContext` for Stop and SubagentStop hooks: Claude gets it as feedback and the turn continues, shown as "Stop hook feedback:" rather than as a hook error.
- 🟢 Added `\$` escapes in skill and command bodies: `\$ARGUMENTS`, `\$1` or `\$name` stay as literal text instead of being replaced.
- 🟢 Made `--resume <id>` set the session ID at startup, so stdio MCP servers get the same `CLAUDE_CODE_SESSION_ID` as hooks and Bash.
- 🟢 Fixed `claude -p` waiting forever on background commands: once input has closed and only background tasks remain, background shells are killed and other background tasks stopped after 5 seconds, unless a background agent or workflow is still running.
- 🟢 Fixed `$TMPDIR` being set to the sandbox's temporary folder for all Bash and PowerShell commands; it's now set only for sandboxed ones, and Claude's sandbox instructions say so.
- 🟢 Made creating the per-session `session-env` folder ignore an "already exists" error, the cause of Windows Bash failures on read-only or OneDrive folders.
- 🟢 Fixed managed settings that loaded before the interface started not being applied: the settings change is now replayed at startup, in interactive and print sessions.
- 🟢 Fixed `claude agents` restarting a background session on a new version while it had queued or running tasks or a scheduled task, losing them; automatic background upgrades also skip a session that received input in the last hour.
- 🟢 Added background updating of `claude agents` sessions: each daemon sweep restarts up to three idle sessions still on an older version (remote setting `tengu_bg_prewarm_per_sweep`).
- 🟢 Made the terminal renderer record that it has left the alternate screen when it shuts down, so a later cleanup can't send the exit sequence a second time, such as after leaving the agent view.
- 🟢 Changed the SDK `stop_task` request to succeed when the task is already gone or finished, instead of returning an error.
- 🟢 Fixed keyboard input freezing when a terminal drops a paste's end marker: a paste whose end never arrives is now flushed after 2 seconds of silence instead of leaving input stuck in paste mode.
- 🟢 Fixed hook conditions such as `if: "Bash(git *)"` matching every Bash command that contains `$()`, `$VAR` or quoted strings; the pattern is now tested against the commands inside them.
- 🟢 Fixed deny rules on home-folder paths not blocking Bash commands that reach them through `$HOME`, which permission checks now read as your home folder; a `for` loop that uses certain special shell variables, such as `HOME`, `PATH` or `PWD`, as its loop variable now needs approval.
- 🟢 Stopped a "(no content)" line from appearing in the transcript after panel commands such as `/mcp` and `/plugins` close.
- 🟢 Rewrote command descriptions in the `/` menu, among them `/autocompact`, `/config` ("Open settings"), `/memory`, `/keybindings`, `/tasks`, `/permissions`, `/loops`, `/ultraplan`, `/ultrareview`, `/advisor`, `/remote-env`, `/focus`, `/daemon`, `/goal`, `/workflows`, `/web-setup` and `/chrome`; bundled skills' new short descriptions show only with the menu's kind lanes.
