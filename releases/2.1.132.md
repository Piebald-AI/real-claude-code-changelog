# 2.1.132 ◆◆◆◆

[Back to the changelog](../README.md#changelog)

- 🔴 Made the Bash permission check treat more assignments as too complex to approve automatically: assignments to command-lookup variables (`PATH`, `BASH_ENV`, `ENV`, `CDPATH`, `GLOBIGNORE`, `SHELL`, `FPATH`, `MANPATH`, `MAILPATH`, `BASH_LOADABLES_PATH`, `MODULE_PATH`, and names starting with `LD_`, `DYLD_` or `BASH_FUNC_`), and assignments to integer shell variables such as `RANDOM`, `SECONDS` or `LINENO` whose value holds `[`, a backtick, `$(`, a letter from A–Z or a–z, or an underscore. The check also treats any `for` loop using a name from either group as too complex, even when its values are literal numbers. The command-lookup names and prefixes match regardless of letter case.
- 🔴 Made the Bash permission check also treat these forms as too complex: `export` with an array subscript, `{name}>` redirects that assign a file-descriptor variable, redirect targets starting with `=`, backslash-escaped braces, zsh `$name[expr]`, `$name:mod` and `$+`/`$^`/`$=`/`$~` expansions, `[[ ]]` tests containing an expansion or a command or process substitution, `[` and `[[` tests with a quote where the operator should be, backtick bodies with escapes the parser can't follow, and commands containing an unpaired UTF-16 surrogate.
- 🔴 Fixed the Bash permission parser reading a `#` inside a word as the start of a comment, treating `[[` as a test even when no space follows, and missing backticks and `<(…)`/`>(…)` inside `[[ ]]`; it also now checks redirects on a statement that runs no command of its own, which it used to skip.
- 🔴 Fixed Bash test parsing so single-bracket tests don't absorb shell logical operators or redirects, double-bracket tests handle line breaks and comments after logical operators, and parts of words aren't mistaken for unary operators or closing brackets. Also corrected quote, whitespace and pipe handling in regex and `=` operands, and line continuations before `==`/`!=` operands' closing brackets.
- 🔴 Changed the Bash permission parser to treat arithmetic-expansion results as unknown values instead of literal shell text; double-quoted arguments made only of arithmetic expansion now count as too complex to approve automatically.
- 🔴 Made the Bash permission check's `sed` rule look past `timeout`, `time`, `nice`, `stdbuf`, `nohup`, `command`, `builtin`, `noglob` and safe variable prefixes, so a `sed` that writes files or runs commands asks for approval behind them too; `nice` with a first argument whose value the parser can't resolve is no longer treated as analysable.
- 🔴 Updated the shorter Bash instructions for Opus 4.7 to prefer absolute paths and Read, describe background commands as waking Claude when they exit, and recommend Monitor instead of foreground sleep when Monitor is enabled. These instructions need `CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=1` or an existing remote switch that's off by default; the background-command advice is omitted when background tasks are disabled.
- 🔴 Removed the instruction to use Read for later output from the Bash and PowerShell `run_in_background` parameter descriptions.
- 🔴 Added a default auto mode allow rule for scheduling Claude Code tasks with `CronCreate`, `CronDelete`, `CronList` or `RemoteTrigger`.
- 🔴 Gave auto mode's second-stage and tool-call classifier requests up to 120 seconds, with each attempt cut off at 60 seconds; every classifier request used to time out after 30 seconds, which the first stage keeps.
- 🔴 Changed WebFetch to return a normal result for a non-2xx response ("The server returned HTTP 404 Not Found…", with the `Retry-After` seconds when the server sends them, suggesting an authenticated tool such as `gh` or an MCP fetch tool when a page needs sign-in) instead of failing with an error, and to handle `303` redirects like the other redirect codes.
- 🔴 Stopped deferring the AskUserQuestion tool behind tool search, so its full definition is always sent.
- 🔴 Updated the bundled `/claude-api` skill's Managed Agents documentation with three new reference files (multiagent sessions and threads, outcomes, webhooks), MCP OAuth credential validation and new per-agent limits (up to 128 tools and 20 skills, where it said 50 and 64).
- 🔴 Removed the passage in the `/schedule` skill's description that told Claude to proactively offer scheduling a follow-up agent after finishing work; the skill is available only behind a remote switch that's off by default.
- 🔴 Told prompt suggestions to stay silent when a suggestion could be unsafe or touch a sensitive topic (security incidents, credentials, harm, private data), even during legitimate security work.
- 🔴 Stopped showing starter prompt examples when the conversation already has messages, including after resuming a conversation before its first new submit.
- 🔴 Made `/team-onboarding` run at low effort.
- 🔴 Changed the team onboarding share tool, which with `/team-onboarding`'s sharing step sits behind a remote switch that's off by default: it can now delete a guide and target one by `short_code`, uploads the local `ONBOARDING.md` when it checks, needs a claude.ai sign-in, and `/team-onboarding` tells Claude to call it right after the draft and again after your review.
- 🔴 Stopped print-mode (`-p`) sessions waiting for the versioned plugin system to initialize before they start; it now finishes in the background, the session waits for it before exiting, and its duration is reported as a `plugins_init` timer.
- 🔴 Changed when the background housekeeping pass first runs, using a `.last-cleanup` file in the config folder: if it hasn't run in the last 24 hours, print and SDK sessions run it after 5 seconds instead of 10 minutes; if it has, interactive sessions now wait about 20 minutes instead of 10.
- 🔴 Made sandboxed Bash commands get `TMPDIR` from `CLAUDE_CODE_TMPDIR` when it's set (ahead of `CLAUDE_TMPDIR` and `/tmp/claude`), and set `CLOUDSDK_PROXY_TYPE=http` instead of `https` for `gcloud` behind the sandbox proxy.
- 🔴 Made `CLAUDE_CODE_ENABLE_CFC=1` turn on Claude in Chrome in print and SDK sessions; non-interactive sessions used to ignore it unless Chrome was requested explicitly.
- 🔴 Moved the OAuth token-refresh lock into the config folder as `.oauth_refresh.lock`, instead of placing it beside that folder, and stopped resolving the folder through `realpath` when taking the lock.
- 🔴 Stopped using the fullscreen renderer in sessions started through the `local-agent` entrypoint.
- 🔴 Changed `/tui fullscreen` and `/tui default` to save your choice when that renderer is already running and no `tui` setting is saved yet (answering "Already using…" without restarting), and to drop `CLAUDE_CODE_DISABLE_ALTERNATE_SCREEN` when they restart Claude Code.
- 🔴 Added a remote switch (off by default) that makes the fullscreen renderer the default when no `tui` setting or environment variable decides; those sessions show "Using flicker-free rendering · /tui default to go back" and, after five showings, save `tui: "fullscreen"` to user settings.
- 🔴 Added precomputed compaction behind a remote switch (off by default): in sessions that compact when a request overflows, a summary is prepared in the background once the context reaches the compaction threshold, and when a request is then rejected as too long, that summary replaces the conversation instead of a new compaction.
- 🔴 Added a `WaitForMcpServers` tool behind a remote switch that's off by default, for models classified as lacking tool-reference support (Haiku by default). While servers are still connecting, it lets Claude wait up to 5 seconds, and a missing tool from one of those servers gives a hint to use it.
- 🔴 Added a remote-controlled option, off by default, for print and SDK startup to skip the initial connection wait for ordinary MCP servers and claude.ai connectors; servers marked `alwaysLoad` still wait, and `MCP_CONNECTION_NONBLOCKING=0` overrides the option.
- 🔴 Cut the lists of still-connecting MCP servers in tool search results and in reminders to Claude at 30 names, followed by "…and N more".
- 🔴 Changed claude.ai connector error handling to unwrap the first `data: ` payload of an HTTP error sent as an event stream. Unretried 401 responses still pass through unchanged.
- 🔴 Added `/radio` ("Listen to Claude FM lo-fi radio"), which opens a YouTube live stream in the browser, behind a remote switch that's off by default.
- 🔴 Added a Compliance row to `/status` listing the compliance labels in the organization's policy limits, such as "HIPAA" and "ZDR (Zero Data Retention)".
- 🔴 Removed the extra usage credit offer ("$N in extra usage, on us · third-party apps · /extra-usage") from the welcome screen, `/usage` and the startup tips, along with the check for the organization's credit grant.
- 🔴 Changed the reply to an unknown slash command (`Unknown command: /x`, with any "Did you mean" suggestion) to a warning line; it used to be added as a user message after a note telling Claude to ignore local command output.
- 🔴 Limited the startup tip "Run /terminal-setup to enable convenient terminal integration…" to terminals `/terminal-setup` can configure (on Linux: VS Code, Cursor, Windsurf, Alacritty and Zed).
- 🔴 Changed a prompt-type Stop hook that a skill adds to the session to be removed once it lets Claude stop; it used to keep running at every later stop.
- 🔴 Moved `/mobile` and `/effort` onto shared Ctrl+C/Ctrl+D exit handling: one Ctrl+C no longer closes `/mobile`, and one Ctrl+C or Ctrl+D no longer cancels `/effort`. With the default keybindings, pressing the same shortcut twice within 800 ms exits Claude Code; Esc still closes either dialog, and plain `q` still closes `/mobile`.
- 🔴 Fixed text cut to a width of one column showing "…" even when it already fit.
- 🔴 Removed the special case that scrolled modal scroll views when repeated `j`, `k`, `g`, `G`, space or `b` presses arrived together as one input.
- 🔴 Made the Runtime in a remote session's details count up every second while the session runs.
- 🔴 Clamped background-session ages to zero when their creation time is in the future.
- 🔴 Added a remote switch (off by default) that turns on session persistence for Remote Control sessions.
- 🔴 Changed Remote Control auto-titling to reuse a local AI title and otherwise wait for the generated title instead of first publishing a shortened first message. A pending generated title is discarded if a new local AI title appears, and an automatic title update is skipped if the remote-title lookup fails.
- 🔴 Reworded the system-prompt guidance on offering `/schedule` follow-ups, which sits behind a remote switch that's off by default (offer at 75%+ odds instead of 85%+, for follow-ups more than two hours away), and added a stricter variant behind another remote switch that offers only for a quoted artifact with a date, ETA or condition.
- 🔴 Removed `until <condition>` from `/loop`'s argument hint, which shows only behind a remote switch that's off by default; `/loop` never acted on it.
- 🔴 Made background sessions skip onboarding and the workspace trust dialog, counting trust as accepted for that session, while still asking about pending project MCP servers; background sessions and the agents view work only behind a remote switch that's off by default.
- 🔴 Made a background session that's ready to display leave a starting, resuming, adopted or crashed state even when its saved tempo still says active; sessions waiting on a prompt stay blocked.
- 🔴 Changed the detach key shown when attaching to a background session from "Ctrl+B then d" (and "Ctrl+Q" in `claude attach`'s help) to "Ctrl+Z".
- 🔴 Saved a background job's daemon worker ID in its session record, updated it after respawns, and used it for alive, stop and replacement checks instead of assuming it always matches the job ID.
- 🔴 Saved prompt suggestions for a background session that's waiting on you and showed them as the reply placeholder in the agents view, where Tab accepts one.
- 🔴 Made the left-arrow shortcut into the agents view available once you've used background sessions, instead of only behind its own remote switch.
- 🔴 Made `claude stop` mark the session stopped in its record, and made the daemon mark sessions failed when their process disappeared while it was down, when it reaps them, or when they keep stalling at startup.
- 🔴 Stopped resetting the one-hour input-activity timer in the daemon's normal worker-recovery path after restart; that path now has its own two-minute grace period before cleanup.
- 🔴 Changed the agents view to list a session whose last activity failed as done instead of blocked.
- 🔴 Made the agents view's working, awaiting-input and completed totals use live activity as well as the saved session state.
- 🔴 Made background-session commands cope better with a slow daemon: starting it waits up to 10 seconds instead of 5, a reply restarts an unreachable daemon and tries again, and a dispatch retries twice on a stale handle and resends after a missed acknowledgement.
- 🔴 Reworded the `claude daemon` service messages on Linux: install, start, stop and restart now say the service isn't available there and the daemon runs on demand instead, and uninstall says it isn't available.
- 🔴 Let `/background` with no arguments run immediately, even while Claude is responding.
