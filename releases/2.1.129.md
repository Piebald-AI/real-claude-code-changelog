# 2.1.129 ◆◆◆◆

[Back to the changelog](../README.md#changelog)

- 🔴 Changed file writes to reject a symlink at the destination and use random, exclusively created temporary files. Project/local settings also reject a symlinked parent outside the user settings directory; user-directory settings and global configuration writes still allow symlinks.
- 🔴 Added organization-controlled permissions to claude.ai connector tools: blocked tools disappear from Claude's tool list, while ask-only tools always need approval, even with allow rules, bypass mode or auto mode, and don't offer a permanent-approval choice.
- 🔴 Allowed permission-rule tool names containing underscores to start with a lowercase letter, and stopped treating inherited JavaScript object properties as custom permission validators.
- 🔴 Changed the default model for API-key and workload-identity sessions on the Anthropic API and Claude Platform on AWS from Sonnet to Opus, with 1M context when eligible, and gave usage-based Enterprise subscribers the Opus default and model choices previously used by Max subscribers.
- 🔴 Changed the signed-out/API-key `/model` list on the Anthropic API and Claude Platform on AWS to match the new Opus default: Opus appears only as the Default row, Sonnet gets its own row, and the additional Opus 1M choice appears only when the default Opus model isn't already using 1M context; custom model overrides still take precedence.
- 🔴 Changed skill-listing budgets to keep full descriptions for the most-used skills and omit descriptions for lower-ranked skills when space runs out, instead of shortening every description together.
- 🔴 Added `${CLAUDE_SKILL_DIR}` expansion inside a skill's `allowed-tools` entries, including plugin skills.
- 🔴 Changed command lookup so local skills and plugin commands or skills take precedence over a bundled skill with the same name.
- 🔴 Added `claude plugin validate` warnings explaining that `CLAUDE.md` and `CLAUDE.local.md` at a plugin's root aren't loaded as project context.
- 🔴 Changed plugin downloads to keep their source-derived cache directory instead of renaming it to the plugin's declared name, and stopped install/update cleanup from deleting an old directory that contains the new one.
- 🔴 Added a more persistent autonomous-loop prompt behind `CLAUDE_CODE_LOOP_PERSISTENT` or a remote switch that's off by default: it tells Claude to continue unfinished work, check the branch's PR and sibling work before stopping, and stay available when a check finds nothing to do.
- 🔴 Added a remote switch, off by default, that disables session recaps and hides their `/config` setting.
- 🔴 Expanded reactive compaction behind `tengu_cobalt_raccoon`, which is off by default, from 1M-context models to other models in interactive sessions. It also stops excluding Opus 4.7 sessions whose automatic-compaction window comes from `tengu_amber_redwood2`.
- 🔴 Added a background-session startup watchdog that marks a session still showing `starting…` after 45 seconds as needing input, with a request to open it and finish setup; `CLAUDE_BG_STARTUP_WEDGE_MS` changes the delay.
- 🔴 Changed background-session status classification to spell out that a question about whether or how to deliver the requested work leaves a session blocked while an offer of optional extra work doesn't, recognize more statements of ongoing work, and write phone-notification status lines that name the concrete file, error or result; saved status and result text can now use up to 800 characters instead of 180. Its model-backed instructions also treat a finished handoff to another party as done, but keep a session working when the agent plans to check again, even while awaiting approval.
- 🔴 Cleaned up the "needs input" text a background session shows after an authentication failure: the repeated "Please run /login" and "Failed to authenticate." wording is removed from the error it appends, which can now run to 800 characters instead of 160.
- 🔴 Changed the background-session classifier to default to the small-fast model with thinking disabled; its remote configuration now selects the small-fast or main model instead of accepting a model-name override.
- 🔴 Added the last 200 characters of a worker's startup output to its crash and respawn details when it exits before initialization.
- 🔴 Changed background-session startup to fall back to a temporary daemon when an installed daemon service can't be reached within five seconds, instead of refusing to start the session.
- 🔴 Changed a newly created background session without a prompt or scheduled trigger to blocked, with `send a prompt to start`, instead of leaving it idle without a request for input.
- 🔴 Changed deleting a completed session from the agents view to remove its worktree even when it has uncommitted changes; a worktree on a different branch is still kept.
- 🔴 Added locking around background-session pinning and manual ordering so simultaneous agents-view writes don't overwrite each other.
- 🔴 Changed replies and prompt-based respawns to show the start of the new prompt as the session's status detail instead of the previous detail.
- 🔴 Added pasted-image attachments to the agents-view dispatch composer, writing the images into the job directory and passing their file paths in the new session's prompt.
- 🔴 Changed agents-view activity previews to omit system-reminder and task-notification blocks and use the first nonempty line of the user's message.
- 🔴 Changed agents-view details to wrap long status and input-needed text, keep relative ages updating after the first minute, and show the information pane's last update as a relative age.
- 🔴 Added an on-screen error when renaming a session in another terminal fails because that session doesn't respond.
- 🔴 Fixed agents-view attachment recovery to reconnect when a respawn reports that the session is already alive.
- 🔴 Added warnings for extra arguments ignored by background-session verbs and daemon subcommands, while leaving supported debug flags alone.
- 🔴 Disabled `/feedback` on Claude Platform on AWS and Amazon Bedrock's Mantle endpoint, with provider-specific messages pointing to the issue tracker.
- 🔴 Changed the bundled Anthropic SDK to merge `ANTHROPIC_CUSTOM_HEADERS` itself, so clients created outside the main request factory, including setup-wizard model checks, receive those headers too.
- 🔴 Changed Mantle API-key authentication to use a bearer header that the main client factory then removes, leaving requests made with `AWS_BEARER_TOKEN_BEDROCK` without that credential.
- 🔴 Changed Bedrock streaming to throw an API error when an event-stream chunk contains an error object, instead of passing that object through as a normal response event.
- 🔴 Extended AWS credential-error recovery and client recreation to Claude Platform on AWS and Mantle, rather than only Bedrock, and started refreshing Mantle credentials during startup.
- 🔴 Made the Vertex AI setup (`/setup-vertex`) also clear a saved `CLAUDE_CODE_USE_MANTLE`, as it already did for the other provider switches, so a Mantle choice no longer stays on after you set up Vertex.
- 🔴 Changed `/autofix-pr` to watch several pull requests at once and reuse an already-running remote watcher for the same PR instead of launching another.
- 🔴 Allowed cloud sessions to create, inspect and archive other web sessions using `CLAUDE_CODE_OAUTH_TOKEN` or the token file descriptor when no saved login is available, and added more specific session-creation failure messages.
- 🔴 Changed `/remote-control` to open sign-in and wait for Trusted Device enrollment when the organization requires it, instead of only telling the user to run `/login`.
- 🔴 Added a remote switch, off by default, that stops proactive Trusted Device enrollment and explains that enrollment is temporarily unavailable when it prevents Remote Control.
- 🔴 Stopped the PR badge from showing review-state emoji; the PR number and link still appear.
- 🔴 Changed plan mode's exploration instructions to mention shell `find` and `grep` alongside the dedicated tools when the native shell-tool mode is available.
- 🔴 Made `CLAUDE_CODE_ENABLE_FINE_GRAINED_TOOL_STREAMING=0` turn off fine-grained tool streaming even when its remote switch enables it.
- 🔴 Changed permission explanations for hook decisions to name `plugin hooks.json`, `SKILL.md` or `settings.json` as the file to edit instead of pointing to `/hooks`.
- 🔴 Changed Channels' unsupported-provider messages to cover all third-party providers rather than naming only Bedrock, Vertex and Foundry.
- 🔴 Fixed daemon-attached sessions to use the originating terminal's Cursor/VS Code wheel-flood detection, and reset keyboard-scroll acceleration when those terminal capabilities change.
- 🔴 Marked an MCP tool result as an error when a required URL interaction is declined or the tool call is canceled.
- 🔴 Removed the keyboard-driven message-actions menu, including its custom keybindings, message-selection highlight, copy actions and edit/expand navigation.
- 🔴 Changed first-run startup to refresh account feature switches right after onboarding finishes and wait up to two seconds for them before continuing.
- 🔴 Added an uncaught-exception circuit breaker that exits with status 1 after ten exceptions within five seconds instead of allowing an exception loop to continue.
- 🔴 Fixed saved-transcript appends to check the last saved message as well as the first, rewriting when that message was replaced in place instead of silently missing the replacement.
- 🔴 Stopped enabling fast mode in `/config` from replacing the selected model when that model already supports fast mode.
- 🟡 (2.1.47) Stopped executing or stripping a skill's `!`-backtick shell interpolation when it's written inside an ordinary inline-code span.
- 🟡 (2.1.92) Expanded tool-input repair to decode string-encoded arrays and objects described by JSON Schema, including local references and union schemas, rather than only Zod object schemas.

- 🟢 Added successful MCP tools with pull-request or merge-request creation names to the `claude_code.pull_request.count` metric and Git-operation telemetry.
- 🟢 Added the API request ID to policy-refusal messages, and read refusal explanations from the response's stop-details event rather than the unfinished message object.
